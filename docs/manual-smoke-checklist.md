# Cellar 1.0 人工验收清单

本清单验证自动测试无法证明的真实 macOS、系统授权、本机工具、网络和 UI 行为。只把实际执行的项目标为完成；没有合适环境时保持未选中，并在交付说明中列为剩余风险。

当前 1.0.0 源码已实现，尚未公开发布。隔离、关闭真实环境读取的只读视觉检查和自动测试不替代本清单；真实 provider 写入、系统 Installer/CLT 对话框、网络、VoiceOver、Dark 与辅助设置等项目仍须单独执行。

## 安全准备

- [ ] 只读检查已说明可能访问 Homebrew/npm 网络并更新各自 cache。
- [ ] 所有安装、更新、卸载、Tap/Registry、Node、`.nvmrc` 和终端配置写入只在可丢弃的专用测试账户/环境执行。
- [ ] 已记录测试前的 Homebrew、npm、nvm、`.npmrc`、`.zshrc` 和项目状态，以便区分 Cellar 的真实影响；不假设事务回滚。
- [ ] 不使用有价值的生产环境测试批量操作、Cask zap、系统 Installer 或维护动作。

## App shell 与窗口

- [ ] 从 Finder 启动后普通前台窗口立即出现，首次默认内容尺寸为 1080 × 720 点且可调整。
- [ ] Dock 显示 Cellar；没有 `MenuBarExtra` 或后台常驻。
- [ ] 全部主页面采用同一原生工具栏与系统自动背景/滚动边缘，不再强制固定背景或硬分隔；分类在左、动作靠右，正文铺满内容栏，滚动指示器不随内容留白缩进。
- [ ] 环境的终端、Brew Tap、npm 软件源、Node.js，维护的检查、清理，以及 Settings 的通用、环境信息均在工具栏切换，内容区不重复分类条；Command-Comma 和菜单 About 路由仍正确。
- [ ] 主侧边栏顺序为 Home、Library、Discover、环境、维护，软件更新功能位于 Library；左下方依次显示 Settings 和 About，没有活动记录入口或相关菜单。
- [ ] 七个侧边栏入口均显示无底色的强调色符号；逐项点击、上下方向键切换、Tab 移出移入及切换窗口后，选中项始终使用灰阶背景，无强调色填充。方向键可以跨越维护/Settings 分组，首尾不循环；VoiceOver 能识别名称与当前选中项。
- [ ] 启动、手动刷新、软件更新检查、setup recheck 和 Node.js 版本读取等 refresh 任务只在右上角刷新按钮内显示系统进度动画；版本安装面板中的版本读取状态能明确识别。
- [ ] Settings 是主窗口 detail 页面，通用保留语言与日志偏好，环境信息展示完整已有环境数据；点击侧边栏、App 菜单或 Command-Comma 都选择该页面，不创建独立设置窗口；菜单重复调用复用主窗口，主窗口不存在时正确重建。
- [ ] 关闭最后窗口和无任务时 `Command-Q` 正常退出。
- [ ] 活动任务期间退出请求被拒绝；任务自行结束后可以退出，界面不提供手动停止。
- [ ] App 退出后没有 Cellar 启动后遗留的 brew、npm、bash 或 zsh 进程。

- [ ] Home 和 About 的主内容区边距为 16 点；Home 摘要分组间距 20 点、独立统计卡片间距 12 点，About 与 Library/Discover 保持各自现有布局；表单字段、Section 标题、操作与键盘焦点正常显示。

## Home

- [ ] 首页工具栏左上角显示本地化页面标题，右侧保留刷新按钮；标题无按钮背景。

- [ ] Home 按 Homebrew、Node、终端环境的顺序显示三个摘要分组，每个统计项各自为独立小卡片，不显示路径、配置文件或 Manager 技术摘要。
- [ ] 本地状态先出现，线上版本随后异步合并，不阻塞首屏。
- [ ] Homebrew 卡片显示 Homebrew 版本、Formula/Cask 与软件更新数量；官网入口是卡片内 Homebrew 字段标题后的统一小号蓝色网站指南针图标，不显示检查时间或重复详情。
- [ ] Node 卡片以两行显示 Node/npm 版本、当前环境全局包与软件更新数量、nvm 状态和 nvm default，不显示检查时间或具体更新名称。
- [ ] 终端环境卡片显示 Command Line Tools 安装状态、Zsh 版本和 Oh My Zsh 安装状态；插件与主题配置位于环境 > 终端，完整路径位于 Settings > 环境信息。
- [ ] 首次读取前所有统计卡片的完整字段与图标立即可见，未知值显示 `—`；后续刷新保留旧值并原位更新，不清空卡片。
- [ ] 只有线上版本明确更高时显示“当前版本 → 最新版本”及其后的圆形向上箭头；单个线上检查失败时保留本机版本，不伪装为需要更新或已经最新。
- [ ] CLT/Homebrew 状态、版本与官网入口紧随对应名称，已安装组件不为官网单独占一行；缺少时 Home 提供必要安装动作。缺少 nvm 时 Home 只显示状态，安装指引位于环境 > Node.js。

- [ ] Discover 默认选择 All，范围控件顺序为 All、Formula、Cask、NPM；All 同时搜索三种来源，保留同名包的类型和 npm 环境／Registry 绑定。某来源缺失或失败时保留其他来源结果并显示提示；批量安装继续选择单一类型。

## 卡片与网站

- [ ] 首页每个统计项为独立小卡片，无整组背景或分割线；图标有浅色圆角矩形底，六个品牌项使用本地彩色 SVG，其余功能项使用本地 Fluent 彩色 SVG（Command Line Tools 使用 Apple 终端官方图标），图标在明暗外观均清晰可辨。窄窗口和较长版本信息不与相邻卡片重叠，官网链接和更新状态正常。

- [ ] Library 和 Discover 使用响应式卡片；卡片左右、上下间距保持 8 点，内容区四周边距为 16 点；卡片 body 无导航动作。
- [ ] 软件卡片左侧图标布局空间固定为 48 × 48 点，在整张卡片内垂直居中；占位底框为 40 × 40 点并在外层空间居中，视觉大小与带透明留白的真实图标接近；右侧名称和 Formula/Cask/NPM Tag 组成标题行，操作按钮靠右；图标右侧、名称和标签下方显示字号不变的灰色简介，与名称左边缘对齐，最多两行，超出以省略号截断；缺少、为空或只有一行时仍预留两行高度，不显示替代文案，空白区域不参与辅助功能朗读；名称到简介、简介到版本行的间距均为 4 点；右侧底部按“V 具体版本 + 蓝色网站文字与图标”排列，版本号与简介左对齐，更新时两端版本均带大写 V，V 使用较小的 caption2 字号，与版本数字同色，V 和数字之间保留细小间距；数字保持 callout 字号并与 V 基线对齐；网站文字与图标共同可点击、均为蓝色，与版本同字号，不使用分割线或简介小卡片背景；版本字号稍大，右上角操作按钮稍大，外层为 Liquid Glass 胶囊；未悬停时内部透明，鼠标移入或按下时只有对应按钮显示浅色背景，禁用按钮不显示悬停背景；Discover 安装按钮使用 `arrowshape.down.circle`，尺寸、玻璃材质与悬停反馈和软件库一致；任务状态显示在元信息行右侧，底部不预留独立状态行；验证无简介、空简介、一行和两行简介的卡片等高，卡片水平与垂直间距统一为 8 点，加载中、失败及成功图标保持相同尺寸，无操作按钮及执行中状态不挤压图标；不重复显示 Node/npm 环境版本；长名称和版本转换无重叠。
- [ ] 已安装卡片通常只显示当前版本；明确需要更新且有目标版本时显示“当前 → 新版本”与圆形向上箭头；不重复显示可用版本和最新状态行。发现中未安装的软件仍显示待安装版本。
- [ ] 网站链接通过系统默认浏览器打开正确 URL；键盘可以单独聚焦主动作和链接。
- [ ] 首页与环境的官网入口只显示蓝色 `safari` 网站指南针，紧随对应名称或标题；目录卡片在版本后显示蓝色“网站”文字与指南针图标，两者共用点击区域；符号大小匹配相邻文字，透明点击区域、键盘聚焦、辅助功能名称和悬停说明保留，官方安装指引用途清楚。
- [ ] Library/Discover 的官方 Cask 使用精确 token 对应的真实图标；第三方 Tap 同名软件不借用官方图标。加载中、404、断网显示首字母，Formula/npm 使用通用图标；图标切换不改变卡片高度，不裁切 Logo；真实软件图标仅有极轻的柔和阴影，Light/Dark 下清晰，VoiceOver 不重复朗读名称。类型 Tag 不可点击，网站图标独立可聚焦。
- [ ] 图标成功后再次展示可复用缓存，重启后可读取磁盘缓存；失败短期不重复请求，CDN 超时不影响搜索、安装、更新和卸载，滚动时请求保持有界；快速滚动或切换搜索后，无人需要的排队请求不再下载，当前可见图标不被旧队列持续阻塞。共享图标的一张卡片离开不影响其他卡片，已开始的下载可完成缓存。
- [ ] loading、empty、offline、partial failure、behind/current/ahead/unknown 有文字或辅助功能值，不只靠颜色。

## Library

- [ ] 软件库不显示页面标题或 scope 标题；原生系统 Tab 控件位于窗口 toolbar 左上角且没有空白尾部。默认显示 All、Brew、NPM，选择 Brew 后同一行按内容变宽并在 Brew 后完整显示 All、Formula、Cask，选择 All/NPM 后收起；右侧搜索框始终独立于 Tab 与动作按钮，空间充足时为 380 点，空间不足时可压缩。
- [ ] All、Homebrew、npm scope 与 Formula/Cask subtype 的内容和数量正确。
- [ ] 本地搜索/筛选不发包目录查询请求；新展示的官方 Cask 可以按需请求图标，长列表滚动和筛选保持响应。
- [ ] 默认 1080 点窗口且侧边栏可见时每行两张卡片，放大窗口后自动增加至三列或更多，卡片保持合理宽度且无水平溢出。
- [ ] 软件库类型与单段待更新 Tab 靠左；待更新可点击选中、再次点击取消，切换类型保留选中状态，不显示第二个 All；待更新具有独立 Tab 背景，与类型组有间隔，不连成同一个胶囊。搜索靠右，刷新使用与 Home 相同的独立圆形按钮并位于搜索框右侧；刷新和 Update All 分为两个独立按钮，只有待更新选中时显示 Update All，无更新目标或忙碌时禁用，菜单同步禁用；更新完成保持选中并显示真实空状态。Brew 展开且选中待更新、三种语言及侧边栏最宽时，搜索框始终显示，宽度在 140～380 点之间动态缩放，控件不合并。
- [ ] 类型、子类型、待更新开关和搜索按交集筛选；查询筛出的单个软件执行批量更新时不会更新其他名称、类型或 Node 环境。
- [ ] 每张安装卡片右上角为共享胶囊内带分隔的更新／卸载按钮；只有可靠可更新目标允许更新，卸载仍先确认。
- [ ] 顶部没有重复的 Node 环境说明；主滚动区域覆盖工具栏下方的内容栏，滚动条位于内容栏右缘，卡片、提示和卸载结果一起滚动，卡片保留内容边距。
- [ ] npm 卡片不重复显示 Node/npm 环境版本，包身份与操作仍绑定对应 Node 环境；切换会话 Node 后不会把两个环境的包合并。
- [ ] 单项卸载立即显示任务专用确认与扫描状态；扫描中不能确认，取消不会启动写操作，迟到结果不会重新打开弹窗。图标仍在读取或目录很多时，取消和主窗口交互保持响应；切换目标后旧图标不能覆盖新目标。
- [ ] Library 没有管理模式、批量选择或批量卸载；每次卸载只接受一个卡片目标并显示任务专用确认。
- [ ] 单项卸载结果正确显示，不宣称事务回滚。
- [ ] Cask 卸载弹窗从扫描状态切换到完整清单时，真实 sheet 窗口应随内容扩高，不能仅内部布局变高而窗口仍保持扫描态尺寸；总高度不超过当前主窗口可用高度的 70%；在最小主窗口和放大窗口中分别验证长名称、多行摘要、多语言及长清单。左侧本机图标与名称、右侧应用大小与本次预计移除、底部取消与卸载按钮均固定，只有右侧分类路径及占用明细滚动；明细从固定摘要下方开始，不覆盖按钮，不出现双层滚动、反复尺寸跳动或无法触达的末尾项目。 滚动条位于右侧留白，不遮挡容量或状态图标；路径可在访达定位。
- [ ] 增强 Cask 确认后弹窗与尺寸保持，运行中不能关闭或重复执行；每条路径依实际操作显示旋转进度，确认消失后才显示对号；失败、授权取消、复验失败和受保护路径不显示成功。完成后按保留原因提示处理方式，底部仅“好的”，任务失败原因仍可见。
- [ ] 本地卷可完整检查且不存在相关应用副本时，不因挂载直接保留全部数据；本地卷含同 Bundle ID 副本、不可读、身份变化或预算耗尽时保留；网络卷不触发递归读取。保留项也应显示可读取的占用量，零大小与未知分别表达；权限不足、统计达到上限、路径受限或读取失败应显示具体原因，统计失败不应改变删除资格。系统 Safari 的符号链接应可识别，不能使无关 Cask 的全部关联数据被保留；未知或损坏链接仍保留未知归属。
- [ ] Cask 清单按应用程序、缓存、设置与应用数据、Homebrew 下载缓存分类；长路径可复制，无法读取的大小明确标记，父子路径不重复计入预计移除。

## Discover

- [ ] 工具栏没有“发现”标题，左侧显示 All/Formula/Cask/NPM；360 点搜索框与刷新、批量安装按钮组靠右，搜索在按钮组左侧；范围 Tab 和搜索框各自独立，由弹性空间分隔。Command-F 聚焦搜索，回车提交查询。
- [ ] 页面整体滚动且滚动条位于内容栏右缘；默认空状态水平、垂直居中，结果卡从顶部排列；内容区没有 Registry/Node 摘要、搜索按钮或 50 项结果提示。
- [ ] 空查询不下载完整目录；输入查询后结果有界，新查询或离开页面会安全结束旧查询，界面不提供手动停止。
- [ ] Homebrew Formula、Cask 与 npm Registry scope 清楚可见，同名 Formula/Cask 不混淆。
- [ ] npm 结果卡的身份保留目标 Node 环境，卡片不重复显示环境版本，批量安装确认继续显示实际 Registry 与目标；安装只作用于该环境的全局 package。
- [ ] 单项安装从卡片开始，不出现通用“生成/执行计划”页面；失败后读取真实状态。
- [ ] 批量输入一行一项，正确去空、去重；超过 100 项时拒绝提交。输入、粘贴和删除后支持撤销与重做，行号及安装预览中的名单保持同步。
- [ ] 一个 batch 不能混合 Formula/Cask/npm；预览和一次确认后顺序执行并保留 per-item outcome。

## 软件库中的更新

- [ ] 侧边栏和 Go 菜单没有独立 Updates 入口；在 Library 切换 Pending Updates 查看待更新项，工具栏 Update All 与菜单检查入口都作用于软件库。
- [ ] 空状态在内容区水平、垂直居中，结果卡从顶部排列，页面整体滚动且滚动条位于右缘；内容区没有重复范围标题、更新数量、Node 环境摘要和检查按钮，失败提示与执行结果仍可见。
- [ ] All、Homebrew、npm 与 Formula/Cask scope 正确过滤卡片。
- [ ] current、available 与 behind/current/ahead/unknown 对真实版本关系表达正确。
- [ ] npm ahead/unknown 没有 update 或 downgrade 动作。
- [ ] 单项更新从卡片开始；Update All 只作用于当前可见 scope。
- [ ] All scope 中 provider/type 仍拆为 typed sequential operation，没有混合命令。
- [ ] 批量确认捕获当时筛选后的目标；切换 Tab、状态或搜索后确认不会扩大原批次。项目失败后继续、任务运行至完成、partial completion 和 post-refresh 都正确。
- [ ] 跨 Formula／Cask／npm 更新时后续组显示排队，当前项显示执行阶段；最终复查结束前相关卡片保持校验状态。
- [ ] 检查中、未检查或失败不被显示成“没有更新”；失败后普通 Library 保留已安装软件与版本，更新按钮不可用。
- [ ] `brew update` 只在环境 > Homebrew Tap作为目录数据更新动作，不被查看、卸载或 package update 隐式触发。

## 基础环境安装

### Command Line Tools

- [ ] 已安装 CLT 时显示可用，不提供重复安装动作。
- [ ] 缺少 CLT 时只执行 `xcode-select --install` 并出现 Apple 文档所述系统安装对话框；Cellar 不下载 payload、不模拟许可或安装。
- [ ] 用户取消或系统失败时显示真实状态，不继续假定 CLT 已安装。

### Homebrew

- [ ] 已安装且可用的 Apple Silicon Homebrew 显示 `/opt/homebrew` 和正确版本，不提供覆盖安装。
- [ ] 缺失时只从 Homebrew 官方 latest stable Release 选择精确 `Homebrew.pkg`，并取得该资产的有效官方 SHA-256。
- [ ] 官方 SHA-256 缺失、格式无效或与下载文件不匹配时 fail closed：不打开 package，显示具体原因和 Homebrew 官方网站链接。
- [ ] package signature 或 Gatekeeper assessment 无法完成、结果缺失、无效或失败时同样 fail closed，不允许用户绕过检查继续打开。
- [ ] 全部验证通过后只交给系统 Installer 打开；Cellar 不承诺系统将显示哪种提示，不请求或保存密码，也不运行自己的 `sudo`。
