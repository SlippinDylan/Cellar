# Cellar 1.0 产品需求

状态：1.0 产品契约；源码已实现，未公开发布

更新日期：2026-11-13

本文是 Cellar 1.0 用户行为、范围和验收的唯一权威来源。源码实现与自动验证不代替真实环境人工验收。组件边界见[总体架构](../architecture/macos-app-architecture.md)，发布范围见[1.0 交付范围](v1-mvp.md)，外部依据见[研究文档](../research.md)。

## 1. 摘要

Cellar 是面向 Apple Silicon Mac 的原生开发环境管理工具。它把 Homebrew Formula、Homebrew Cask、npm 全局包、Node/nvm 与终端配置组织为“查看、发现、安装、更新、卸载和维护”等用户任务，而不是要求用户先理解不同命令行工具的页面结构。

统一界面不抹平 provider 差异。每项操作始终保留 Formula、Cask 或 npm 身份、明确的 Node 环境、真实副作用和失败边界；批量操作不是事务，也不承诺回滚。

## 2. 背景与用户

目标用户是在 macOS 上维护本机开发工具、但不希望反复记忆多套 CLI 语法的开发者。他们需要快速回答三个问题：本机有什么、有什么可更新、一个操作会影响哪里。

1.0 在受控进程、Homebrew 查询和 mutation、Node Manager schema v1、Shell adapter、部分失败保留与 Manager 快照的基础上，已实现任务信息架构、官方目录、环境安装引导、批量编排、本地文件日志与任务反馈、本地化和可访问性支持。

## 3. 目标与成功标准

| ID | 目标 | 1.0 验收信号 |
|---|---|---|
| G-01 | 任务导向 | 用户从 Home、Library、Discover、环境或维护完成任务，无需先选择技术模块 |
| G-02 | 真实且清楚 | 卡片显示 provider/type、版本和状态，操作绑定明确的目标环境；未知状态不伪装为最新 |
| G-03 | 安全写入 | 写操作有明确范围、适当确认和 post-refresh，并保留部分完成结果 |
| G-04 | 可恢复读取 | 一个 provider 或线上检查失败时，其他本地数据继续可用 |
| G-05 | 原生体验 | 支持键盘、VoiceOver、系统外观、窄窗口和标准 macOS 菜单快捷键 |
| G-06 | 国际化 | English、简体中文、繁体中文、日本語、한국어、Deutsch、Français、Español 覆盖所有用户可见字符串，默认跟随系统 |
| G-07 | 低资源占用 | 空闲时无轮询；独立 IO 只使用有界并发；大列表和状态更新无持续高频工作 |

## 4. 信息架构

主窗口使用两栏 `NavigationSplitView`。窗口默认及最小内容尺寸均为 1080 × 720 点，可由用户放大并由系统恢复尺寸。

Home、Library、Discover、环境、维护和 Settings 的主内容区四周边距及其他区块间距统一为 16 点，卡片之间的横向、纵向间距保持 8 点。环境、维护和 Settings 使用单列分组样式：正文边距 16 点，组间距 16 点，组内边距 16 点；紧凑状态和操作按内容组织，字段与控件内部保留适合其内容的排版。

侧边栏主导航顺序固定为：

1. Home
2. Library
3. Discover
4. 环境（Environment）
5. 维护（Maintenance）

侧边栏左下方依次显示 Settings 和 About，不提供活动记录页面或相关导航、菜单。环境管理外部开发工具与配置；维护承接检查与清理；Settings 分为通用与环境信息，分别管理 App 偏好和展示完整环境信息。Settings 是主窗口内的真实导航页面，选择后在 detail 区域显示设置内容，不打开独立设置窗口。App 菜单和 Command-Comma 通过共享导航意图前置或重建主窗口并选择 Settings；重复调用复用同一主窗口。App 是普通前台应用，不提供 `MenuBarExtra`，不在关闭最后窗口后后台驻留。

侧边栏仅对当前选中项显示与侧栏材质融合的浅灰圆角背景，不额外绘制焦点边框；文字保留正常前景色，图标使用无底色的 SF Symbol 并跟随系统强调色。Settings 和 About 使用同一套图标和选中样式。鼠标切换、键盘聚焦及窗口重新激活后，选中背景均保持灰阶并适配系统外观；方向键可连续切换七个入口，首尾不循环，Tab 导航与辅助功能选中反馈保持可用。

无活动任务时，关闭最后窗口和 `Command-Q` 退出 App。有活动任务时，本次退出请求被拒绝；运行中只显示进度、不提供手动停止，任务结束后用户可再次退出。

所有登记为 refresh 的任务统一在主窗口右上角的刷新按钮中显示系统进度动画；页面内容区不重复显示刷新动画或刷新中说明。

所有主页面采用统一的原生窗口工具栏：Home 在左侧显示当前页面标题，其他页面的分类或范围入口位于左侧，刷新与页面动作靠右；工具栏背景、悬停反馈和滚动边缘由系统自动管理，不强制固定背景或硬边界。正文容器铺满内容栏，留白只作用于内容；表单、表格和滚动视图保留各自的原生滚动，不在外层再套第二个滚动容器。

网站链接使用小号蓝色 `safari` 指南针图标，无额外背景或边框，通过系统浏览器打开。Library/Discover 卡片在图标前显示同为蓝色的“网站”文字，文字和图标共同组成一个链接；其他页面保留仅图标入口。字号和字重匹配相邻文字；用途通过悬停说明和辅助功能名称提供，并保留透明点击区域。

### 4.1 Home

Home 依次显示 Homebrew、Node/npm/nvm 与终端环境摘要，不显示路径、配置文件或 Manager 技术信息。

- Homebrew：安装状态、Homebrew 版本、Formula/Cask 数量和软件更新数量；官网入口紧随卡片内的 Homebrew 字段标题，使用统一的小号蓝色网站指南针图标打开系统浏览器。
- Node：当前受控 Node/npm 版本、当前 Node 环境的 npm 全局包数量、软件更新数量、nvm 状态和 nvm default。
- 终端环境：Command Line Tools 安装状态、Zsh 版本和 Oh My Zsh 安装状态；插件与主题配置位于环境 > 终端，完整版本和路径信息位于 Settings > 环境信息。
- 三个摘要区中每个统计项各自使用独立小卡片，卡片间距 12 点，不使用整组背景或格子分割线；左侧图标放在浅色圆角矩形内；Homebrew、Node.js、npm、nvm、Zsh、Oh My Zsh 使用随 App 打包的彩色品牌 SVG，Formula、Cask、更新、全局包、默认版本使用本地 Fluent 彩色功能 SVG；Command Line Tools 按用户选择使用本地打包的 Apple 终端 App 官方图标，不改变检测与安装语义，底框使用近白色与少量主题色渐变，并通过柔和阴影表现层次，图标本体使用更轻的阴影；npm 图标较其他品牌图标缩小。两处更新统计统一使用向上箭头，底框仍保留少量状态色。进入页面时完整结构立即显示；尚未读取的值显示 `—`。已有成功结果在刷新期间继续保留，并在新结果到达时原位更新，不把卡片清空为 loading 页面。
- 本机版本与线上版本只有在能够可靠判断本机落后时才显示“当前版本 → 最新版本”，并在最新版本后显示圆形向上箭头；相同、领先、检查中、检查失败或无法比较时只显示本机版本。Home 不显示检查时间、刷新时间、重复的最新状态或具体更新名称。
- 本地状态先显示，线上版本和更新检查随后异步完成；线上失败不能清空本地状态。
- 缺少 Command Line Tools 或 Homebrew 时，Home 在终端环境或 Homebrew 对应区域提供必要的安装动作；缺少 nvm 时只在摘要中显示状态，安装指引保留在环境 > Node.js，不在 Home 重复入口。已安装组件的官网入口与名称同行，不单独占一行。

### 4.2 Library

Library 展示已安装软件，提供 All、Homebrew、npm scope；Homebrew 下提供 Formula 与 Cask subtype scope。

- 软件库不显示页面标题；窗口 toolbar 左上角使用系统自动样式的原生 `NSSegmentedControl`，只承载 Tab 而不创建空内容容器。默认单行显示 All、Brew、NPM；选择 Brew 时切换 toolbar item identity，在同一行于 Brew 后显示 All、Formula、Cask，并按标题内容重新计算整体宽度；离开 Brew 时收起，并保留上次 Brew subtype。另设独立的 Pending Updates 单段 Tab，类型组与待更新使用各自的原生分段背景，不共享连体工具栏背景，中间保留间隔：点击选中筛选待更新内容，再次点击取消选中；不再显示第二个 All。切换类型保留待更新选中状态，类型、状态和搜索条件按交集筛选。右侧原生搜索框始终显示，宽度按剩余空间在 140～380 点之间动态调整；Brew 展开、选中待更新或窗口空间不足时优先压缩搜索框，但不与 Tab 或刷新按钮合并。
- 使用卡片和本地搜索/筛选。
- 默认 1080 点窗口且侧边栏可见时，软件库卡片每行两列；窗口变宽后自动增加列数，卡片宽度随可用空间调整。
- 工具栏下方由单个主滚动区域占满内容栏，卡片、提示和卸载结果一起滚动；内容保留边距，滚动条位于内容栏右缘。页面顶部和 npm 卡片不重复显示 Node/npm 环境版本，操作仍绑定明确的所属环境。
- 类型与待更新 Tab 靠左，搜索框靠右，刷新采用与 Home 相同的独立圆形按钮并位于搜索框右侧；刷新和 Update All 是两个独立按钮，只有待更新选中时显示 Update All，没有可执行目标或任务执行中时禁用，菜单同步禁用条件。更新完成后保持待更新选中状态；展开或收起 Brew 不改变右侧对齐。
- npm 卡片不重复显示所属 Node/npm 环境版本；包身份和操作保留 Node 环境，不把多个 Node 安装的全局包合并成整机唯一集合。
- 卡片右上角以 Liquid Glass 胶囊形按钮组提供单项更新与卸载；更新按钮仅在可靠 behind 且目标仍属于当前版本和环境时显示，单项更新直接开始。单项卸载使用一次任务专用确认；Library 不提供管理模式、批量选择或批量卸载。
- Cask 单项卸载立即打开任务专用弹窗并读取清理清单；扫描期间不可确认，取消后不重新弹出迟到的结果。上方左侧固定本机应用图标和名称，右侧固定应用大小及本次预计移除摘要；只有下方的应用程序、缓存、设置与应用数据、Homebrew 下载缓存分类明细滚动。底部取消与卸载按钮固定，弹窗总高度不得超过当前主窗口可用高度的 70%，内容少时收缩。大小未知明确展示，不计作零；预计移除不重复计算父子路径。 路径可在访达中定位，滚动条与容量及状态列分离。确认卸载后保留原弹窗和执行前尺寸（父窗口缩小时仍遵守高度上限），不允许关闭或重复确认；逐路径显示正在移除状态，只有确认路径已不存在才显示完成对号。完成后保留全部清单，按保留原因提示处理方式，底部只显示“好的”。删除资格与大小统计独立：保留项同样尝试有界统计，权限不足、统计上限、路径受限、文件变化或读取失败分别说明；统计失败不改变路径归属或删除资格，也不将未知计为零。
- Cask 的增强卸载仍由 Homebrew 执行 standard；不静默启用 zap，不把确认范围外的路径纳入清理。数据清理及权限边界见第 7.5 节。
- 确认增强 Cask 卸载后，先对清单内精确应用路径与 Bundle ID 匹配的运行实例请求正常退出，并确认实际结束；拒绝、超时、身份变化或重新启动时不强杀、不继续删除运行中应用的数据。退出写回的数据仍按原清单逐项复验，变化的文件保留并说明，不扩大已确认路径范围。
- 应用定位区分 Homebrew artifact 的来源与安装目标，优先使用已解析的准确目标，旧格式结合已保存的 appdir 配置。pkg 安装可从明确的卸载应用路径识别身份；无法可靠定位时明确标记分析不完整。残留候选可采用 Cask 中精确的允许 Library 路径，拒绝通配符、厂商父目录及共享路径，不执行完整 zap。


### 4.3 Discover

Discover 是 Homebrew Formula、Homebrew Cask 和 npm Registry 的统一搜索入口。scope 必须清楚可见，结果保留 provider/type 身份。

- 窗口工具栏不显示页面标题；左侧使用与批量安装弹窗共用的 Liquid Glass 分段组件，显示 All、Formula、Cask、NPM，默认选择 All；固定 360 点搜索框靠右，紧邻其右侧的刷新与批量安装按钮组。范围 Tab 与搜索框分别使用独立外观，由弹性空间分隔，不共享连体背景。搜索通过回车提交，Command-F 聚焦当前搜索框。
- 页面由单个主滚动区域覆盖内容栏，滚动条位于右缘；默认空状态在可见内容区水平、垂直居中，搜索结果从顶部排列。内容区不显示默认 Registry、整页 Node 环境说明、结果数量提示或搜索按钮。
- All 并发搜索 Formula、Cask 和 NPM，保留来源身份和 npm 的有效 Registry／Node 环境绑定；每个来源默认最多 50 项、上限 100 项。某来源不可用或查询失败时显示来源提示，其他成功结果继续展示。批量安装仍只接受一个明确 provider/type。
- 空查询不请求完整远端目录；搜索结果有界。新查询或页面生命周期变化会在内部结束旧查询，界面不提供手动停止。
- 结果卡显示名称、类型、可用版本、最多两行说明、网站链接和一个状态相关主动作。
- Discover 与 Library 使用相同的 360 点卡片最小宽度；默认 1080 点窗口且侧边栏可见时每行两列，窗口变宽后自动增加列数。
- npm 结果卡的身份保留目标 Node 环境，卡片不重复显示环境版本；搜索与安装绑定实际有效 Registry，批量安装确认继续显示来源和目标，不因移除页面摘要而改变环境绑定。
- Formula/Cask 同名时不能依靠名称猜测类型。
- 批量安装一次只接受一个明确 provider/type，一行一项，去空、去重，最多 100 项；预览目标后统一确认，逐项保留结果。

### 4.4 软件更新（Library 内）

Updates 不再作为独立页面或侧边栏入口，全部软件更新功能由 Library 承载。

- 使用 Library 已有类型及子类型 Tab，再通过 All／Pending Updates 切换全部已安装软件或待更新项；不另建一套重复的类型筛选。
- 无结果时空状态水平、垂直居中，有结果时卡片从顶部排列。未检查、检查中、检查失败和没有可更新项必须区分；失败提示、执行进度、逐项结果、本地日志以及菜单中的检查入口继续保留。
- 卡片显示当前版本、可用版本和 `behind`、`current`、`ahead` 或 `unknown` 语义状态。
- 只有 `behind` 提供更新动作；npm 的 `ahead` 或 `unknown` 不产生更新或降级动作。
- “Update All”只影响点击时的类型、子类型、更新状态和搜索词筛选后的可更新目标；确认捕获该范围，后续切换筛选不能扩大批次。跨 provider 的 All 视图仍拆成 provider/type 明确的顺序任务，不生成混合命令。
- 单项更新从卡片直接开始；批量更新使用一次任务专用确认。
- `brew update` 只更新 Homebrew/Tap 元数据，通过环境 > Homebrew Tap的右上角刷新入口显式触发，不与包更新、查看或卸载隐式绑定。

### 4.5 环境与维护

环境保留内部 tools 路由，用户界面按 Terminal（终端）、Brew Tap（Homebrew Tap）、npm Registry（npm 软件源）、Node.js 四个分类，首次进入默认选择终端组织。维护是独立的侧边栏入口，按检查与清理分类。两者均使用工具栏左侧的原生分段控件，所选分类保留在 App 状态中，不在正文重复分类条。

- **必要上下文**：操作页面只保留决定当前操作所需的版本、目标环境、实际生效配置及影响范围。必要上下文在短页面贴近可用内容区底部，长页面随滚动内容置于末尾，使用无卡片、居中紧凑排列的系统 caption 次要文字，行间距 2 点、不设置最低行高，只显示实际环境数据和必要状态，不附加解释性说明句；完整路径与环境详情集中到 Settings > 环境信息。目标、不可逆影响、错误和检查结果不能因低强调样式而不清楚。
- **Node.js**：以精简上下文显示 Cellar 当前使用的 Node/npm 版本，再展示 nvm 状态、默认版本与 nvm 管理的已安装版本。检测到 Node 与没有 nvm 安装版本可以同时成立；界面不得把后者表述成整机没有安装 Node，也不根据路径猜测安装归属。当前 Cellar 会话与 nvm 默认版本分别标明影响范围，切换会话不改变已经打开的终端，设置 nvm default 影响之后的 nvm 会话，不能称为全机默认 Node。nvm 未检查、不可用与可用状态分别表达，缺少 nvm 时提供官方安装指引，不执行远端脚本。
- 已安装 nvm 版本使用紧凑行展示版本、使用中／默认标记与操作；当前或默认版本不能卸载。用户明确打开安装入口后才读取官方版本并选择安装，加载、读取失败与没有结果分别表达，不在页面常驻只含加载按钮的空白安装卡片。
- **项目版本**作为 Node.js 的小节，仅为用户通过系统目录选择器明确选择的项目读取或写入 `.nvmrc`。显示项目与当前声明，优先提供可选版本并保留手动输入；写入仍使用原任务专用确认与边界校验。保存只声明项目需要的版本，不自动安装 Node、不自动切换现有终端，也不搜索其他项目。
- **终端**：管理 Oh My Zsh、本机主题与插件；Zsh 文件整理仍放在终端配置中，确认前显示受限移动和修改范围。插件只来自已安装 Oh My Zsh 的内置目录、已安装自定义插件或用户确认的规范 GitHub HTTPS 仓库，不提供推荐目录。必需 git 保持选中且不可取消，主题只来自本机 `.zsh-theme`。插件与主题仍通过一次 Apply 提交，保留草稿、任务确认及逐项部分完成结果；Cellar 永不运行 `chsh`。
- 添加 Tap 与从 GitHub 安装插件通过独立输入弹窗提交，保留原有任务确认；npm 软件源配置直接展示。批量安装不显示标题，分类控件位于弹窗顶部中央，与发现页面共用同一 Liquid Glass 分段组件，不额外叠加背景；操作使用玻璃胶囊按钮。添加 Tap 位于分组标题右侧。
- **Homebrew Tap 与 npm 软件源**：拆成两个独立页面，前者仅管理 Homebrew Tap，后者提供“npm 默认软件源”和“npm Scope 专用软件源”两个分组，并说明 Scope 专用源仅服务于指定组织或命名空间的软件包；Homebrew/Tap 目录数据更新保留在Homebrew Tap 页右上角刷新入口，不升级已安装软件。npm 配置仅以无卡片上下文保留目标 Node 版本与实际生效 Registry，并说明修改的是用户配置层；默认 Registry 的用户／项目／全局配置层详情移至 Settings > 环境信息。scope 查询后保留该 scope 的各层结果，用于解释修改影响，不暗示修改会影响全部 Node 安装或覆盖更高优先级配置。
- **维护 > 检查**：保留 Homebrew 状态检查与 npm 缓存校验；通用的当前会话诊断入口位于 Settings > 通用 > 日志，检查结果与读取失败仍保留对应的详情入口。展示未检查、执行中、完成结果或失败等真实状态；结果围绕对应对象展示，技术输出按需打开。不把已有检查包装成覆盖全部工具的一键体检，不把 Homebrew 建议自动转成修复操作。
- **维护 > 清理**：保留 npm 下载缓存、node-gyp 构建缓存、失效 npm 链接、未使用 nvm 版本和旧 Manager 日志五类已有受限清理。“移除前请查看确切的处理范围”以次要文字显示在分组标题右侧。每项显示名称与简短影响说明，确认前展示已读取的处理范围，不虚构数量或可释放空间；没有候选与无法读取分别表达。一次任务确认、安全候选复验、部分完成和实际结果保持不变，不强制先执行检查，也不提供一键全部清理。

CLT/Homebrew 状态与必要安装引导由 Home 承担，不另建环境安装页。网站入口紧随对应名称或标题，状态与必要操作同行；已安装组件的官网不单独占一行。正文保持 16 点内容边距，操作分组垂直内边距 10 点、内容间距 8 点；操作分组中的单行信息内容最低 32 点、交互控件行最低 40 点、带说明的行最低 52 点，长文字可自然增高；分组保持紧凑。

Homebrew `cleanup`、自动删除孤儿依赖和任意路径清理仍不支持。普通界面不展示原始命令或“生成计划/执行计划”等内部术语。

### 4.6 任务反馈与本地日志

App 不再提供活动记录页面、历史表格或相关菜单。任务反馈与排错日志分别承担当前交互和本地记录职责。

- 安装、配置与维护等任务的操作、scope、阶段和真实批次进度在主窗口正文顶部显示，切换页面后仍可见，最终复查结束前不消失；搜索只在结果区域显示加载状态，不显示全局任务栏；普通 refresh 仍只使用工具栏刷新按钮的进度动画。
- 完成后保留最近一次非刷新任务全部分组的动作、时间、成功/部分完成/失败/已取消状态、原因和逐项结果。用户可展开查看逐项结果并关闭反馈；结果只在当前会话中保留，不受日志等级或文件写入失败影响。
- 运行中不提供手动停止；任务所有者结束、超时或 App 生命周期回收导致内部取消时，仍 post-refresh 已经可能改变的状态，并显示实际完成项。
- 文件日志保存在 `~/Library/Logs/Cellar/`，包括时间、等级、模块、任务标识和去敏的操作/逐项结果。批量部分完成保留成功和失败项，不伪装为整批成功。
- Settings 提供 Trace、Debug、Info、Warning、Error、Critical 六个最低记录等级，默认 Info；仅记录所选等级及以上的后续日志。保存期限可选 7、14、30 天，默认 7 天，并提供在访达中打开日志文件夹的入口。
- 设置立即生效。日志按每次写入的 UTC 日期分文件，单文件最多 10 MiB，超过后分卷；总占用最多 50 MiB。启动、后续写入或调整设置时清理过期日志并按需淘汰最旧文件，避免长时间运行跨日期后仍写旧日期文件。
- 文件 IO 在后台串行执行。目录或文件写入失败在通用设置与共享反馈中明确报告并允许重试，不影响任务执行结果，也不将日志未保存伪装为已保存。
- 任意日志等级都不写入原始命令、stdout/stderr、凭证、环境变量秘密、认证 Registry URL 或不必要的用户绝对路径。技术输出仅在用户显式打开的会话诊断中展示与复制，通用入口位于 Settings > 通用 > 日志；检查与错误的对应详情入口继续保留，并提示截断和敏感信息风险。
- 旧 `activity.json` 不再读取或更新，不自动迁移、删除或隔离；历史摘要不恢复到界面。

### 4.7 Settings 与 About

Settings 在主窗口内分为 General（通用）与 Environment Information（环境信息），工具栏左侧复用软件库的原生分段控件样式，所选分类保留在 App 状态中。软件源与终端仍属于环境中的操作页面，不作为 Settings 分类。

设置正文铺满内容栏，使用单列分组布局：滚动内容边距 16 点、组间距 16 点。通用保留浅色圆角操作分组，行左侧显示名称和说明、右侧显示控件；语言、日志等级与保存期限下拉框使用相同宽度，右边缘对齐。环境信息采用居中、最大宽度 600 点的小票纸面，上下使用细小锯齿边，明暗外观跟随系统；组间以虚线区分，组标题与字段形成层级。短值左标题右信息，长路径在字段名下方以等宽字体完整换行，PATH 按目录逐行显示，文字可选择复制；不设置最低行高。页面不显示额外的环境范围说明。

- 通用的语言默认 Follow System，可显式选择 English、简体中文、繁体中文、日本語、한국어、Deutsch、Français、Español。
- 通用的日志提供最低记录等级、保存期限和打开日志文件夹入口，修改后立即生效；详细保存与隐私规则见 §4.6。
- 通用的“完全磁盘访问权限”仅保留简短用途说明及权限按钮；不提供访达入口或重复的长篇权限引导。点击权限按钮打开系统设置，并使用 PermissionFlow 原版悬浮拖拽引导：用户可将当前运行的 Cellar.app 拖入列表，再手动启用开关；悬浮窗沿用原版无标题栏玻璃样式、顶部提示与关闭按钮及原生 App 拖拽卡片，宽度对齐系统设置右侧内容区，随设置窗口移动和缩放。引导的拖拽提示至少为 10 点常规字重，方向箭头响应系统“减少动态效果”；引导不申请辅助功能或屏幕录制权限；返回 Cellar、离开设置页、点击原版关闭按钮或系统设置退出时结束跟随，不自动重启应用。添加或拖拽完成不等同于授权。设置页初次出现及 App 重新激活时，在后台只读验证当前用户 Cookies 目录能否打开并读取一个目录项，不读取文件内容。验证通过后，原按钮变绿并显示“访问已验证”，仍可打开系统设置管理权限；拒绝、缺失或无法验证时不显示成功，离开页面或较旧检查的迟到结果不得覆盖新状态。这是该受保护目录的实际访问验证，不代表读取了系统完整磁盘访问权限开关，也不保证其他路径可读；不读取或修改 TCC 数据库、不使用私有 API。授权后返回 App 重新验证，仍拒绝时保留简短访问受限提示。共享数据删除边界保持不变。
- 环境信息集中展示已有 Homebrew、Node/npm、nvm 与终端的版本、状态、可执行文件、目录、配置路径及受控 PATH；这些数据表示 Cellar 识别和使用的环境，不保证与已打开终端一致。未知、不可用与读取失败明确区分；原始命令输出和会话日志仍通过诊断入口按需查看，不直接铺入信息页。
- Command-Comma 和 App 菜单继续前置或重建同一主窗口并打开 Settings。

About 独立于 Settings，侧栏位于 Settings 下方；菜单“关于”打开同一主窗口的 About。页面居中显示 128 点 App 图标、名称、版本与检查更新按钮，底部保留 Studio 版权署名，不展示更新通道或开源链接，并在空间不足时支持滚动。

环境中的 Homebrew Tap、npm 软件源与 Terminal 操作按钮继续使用原生胶囊样式，任务专用确认仍保留。Terminal 插件使用右侧多选下拉控件，上半部分为已勾选项、分割线下方为未选项，各组按名称排序，面板加宽并限制高度滚动；每行右侧显示内置或已安装自定义插件来源，无法找到的已选项显示未安装，不推断其仓库来源。主题与插件共用的 Apply 位于编辑区域底部，自定义插件安装独立分组。

## 5. 卡片与交互契约

软件库与发现共享自适应卡片网格，卡片水平、垂直间距保持 8 点，内容区四周边距为 16 点。卡片本体没有导航或点击动作；只有明确控件可触发操作。

每张卡片按数据可用性展示：

- 卡片左侧图标占位空间固定为 48 × 48 点，在整张卡片内垂直居中；真实图标保留原始透明留白，占位底框为 40 × 40 点并在外层空间居中，使视觉大小更接近；右侧稍大的软件包名称和不可点击的 Formula／Cask／NPM 文字 Tag 组成标题行；图标右侧、名称和标签下方显示灰色简介，简介与名称左边缘对齐，最多两行，超出以省略号截断；右侧底部版本号与简介左对齐，网站链接紧随版本号；操作控件位于右上角；长名称截断，网站入口保持独立，不使用分割线；
- 已安装软件通常只显示当前版本数值；只有明确 `behind` 且有可用版本时显示“当前版本 → 新版本”，后接圆形向上箭头。不单列“已安装版本”“可用版本”或“已是最新版本”等状态行；检查中、失败、领先或无法比较时保留当前版本，不显示更新箭头。未安装的发现结果显示待安装版本；
- 语义版本状态继续用于更新资格与辅助功能读取，刷新失败由页面提示，不将未知状态伪装成最新；
- 版本以大写 `V` 为显示前缀，不显示“版本”文字或冒号；前缀使用较小的 caption2 字号，与版本数字同色，并保留细小间距；数字保持 callout 字号，两者基线对齐，位于简介下方；更新时显示“V 当前 → V 新版本”，前缀不进入版本比较或操作参数；
- 简介字号不变，使用系统次要文字颜色，无内部小卡片背景；简介最多两行，无论缺少、为空、一行或两行，均预留两行高度，不使用替代文案；没有简介的预留区域不参与辅助功能朗读。图标尺寸不随文字或窗口宽度变化；名称到简介、简介到版本行的间距均为 4 点，元信息行保留统一高度，任务状态显示在元信息行右侧，不预留独立尾部；卡片保持等高，网格水平和垂直间距均为 8 点；
- Library 提供右上角更新／卸载按钮组，Discover 保留状态相关安装动作，安装图标使用 `arrowshape.down.circle`，与软件库共用 Liquid Glass 外观、尺寸和悬停反馈；无更新资格时隐藏更新按钮，仅显示卸载按钮；更新图标使用绿色 `arrowshape.up.circle`，卸载图标使用红色 `trash`，按钮组外层使用系统 Liquid Glass 胶囊材质，每个按钮保留 28 点点击区域、外层 2 点边距；未悬停时按钮无独立背景，悬停或按下时仅对应按钮显示浅色背景，禁用时不显示悬停背景；
- 版本后方以 callout 字号显示蓝色“网站”文字和指南针图标，两者共享一个可点击区域，通过系统默认浏览器打开网站；没有有效 URL 时不显示入口；
- 执行中的真实阶段或不定进度。

软件库与发现共用上述卡片样式。仅明确属于 `homebrew/cask` 的 Cask 按精确 token 从 CaskFlow/jsDelivr 获取 PNG，不按显示名称猜测，不把第三方 Tap 同名软件映射为官方图标。加载中、缺失或失败时使用名称首字母；Formula、npm 使用本地通用图标。真实软件图标附带极轻的柔和阴影；图标不承担交互或辅助功能名称，不裁切原图，不改变卡片高度。图标按展示需要加载，具有有界内存与磁盘缓存、短期失败缓存及有界并发；卡片离开后移除无人需要的排队请求，仍被其他卡片使用的共享请求保留。取消卡片订阅不记为图标失败；已开始的下载可在期限内完成并缓存，失败不阻塞目录或软件操作。界面使用系统字体、颜色、material 和标准控件，类型 Tag 为低对比度静态标识，不以装饰性玻璃覆盖内容卡片。

键盘必须能到达所有动作，并显示焦点。状态不能只靠颜色表达。支持 VoiceOver 名称/值/顺序、Light/Dark、Increased Contrast、Reduce Motion、Reduce Transparency，以及窄/宽窗口。菜单命令和快捷键覆盖可达的刷新、搜索及常用 toolbar 动作。

## 6. 数据与版本语义

### 6.1 Homebrew

- Formula 与 Cask 是不同身份；查询、安装、更新、卸载和批量操作都保留类型。
- 本机信息以受控绝对 `brew` 返回的结构化数据为准；线上 Homebrew 版本与安装器元数据来自官方来源。
- Cask 的应用本体和 Homebrew 安装记录由 Homebrew 卸载维护。Cellar 在明确 App 路径和 Bundle ID 的基础上，检查受限目录内的精确关联路径；不按软件名或 Bundle ID 做任意模糊删除，不直接修补 Homebrew 安装记录。
- 卸载显式禁止 Homebrew 自动更新和 autoremove。

### 6.2 Node、npm 与 nvm

- npm 1.0 只管理全局包，不管理项目依赖。
- 全局包属于明确 Node 安装。默认启动环境优先解析 `~/.nvm/alias/default`；缺失、循环或无法匹配时不猜测最新版。
- Finder/Xcode 启动不读取 `.zshrc`。受控 PATH 只加入明确解析的默认或本次会话 Node `bin` 和批准的系统路径。
- npm Registry 搜索与 Node runtime 管理是不同职责。
- `npm outdated` 或线上元数据失败是独立部分失败，不能抹掉 Node/npm 版本、包列表和配置。

### 6.3 版本状态

在可以可靠比较时，版本状态为：

- `behind`：可用版本高于当前版本；允许更新。
- `current`：当前与可用版本相同。
- `ahead`：当前版本高于线上/Registry 版本；只展示，不自动降级。
- `unknown`：缺失、非可比较版本或检查失败；不声称已是最新，也不提供更新。

## 7. 写操作与安全边界

### 7.1 确认规则

| 动作 | 用户确认 |
|---|---|
| 单项安装、单项更新 | 从卡片直接开始，不显示通用计划页 |
| 批量安装、批量更新 | 预览明确 scope 和目标后一次确认 |
| 单项卸载、Cask zap | 一次任务专用确认，说明不可回滚与影响范围 |
| Tap、Registry、Terminal、`.nvmrc` 等配置修改 | 一次任务专用确认 |
| cleanup 类受限维护 | 一次任务专用确认并列出精确候选；Homebrew cleanup 不支持 |

内部仍使用强类型计划、时效和状态指纹保护高风险操作。确认后的目标或状态变化必须拒绝执行并要求用户重新开始。所有 mutation 在有能力处理结果的层保存退出状态和逐项目结果，完成、失败或内部中断后读取真实状态。

### 7.2 批量与并发

- 同一时间只执行一个全局写任务；重复提交不启动第二项。
- 每次提交只包含一个 provider/type；跨 scope 的用户动作拆为清楚的 typed operation。
- 批量 install/update 顺序执行；单项失败后继续未执行项。每项执行前重新确认原有规范身份、来源、目标版本和目的地，不能因等待较久而沿用过期计划，也不能静默改用新目标。已达到确认目标的项目显示跳过，不计入新增安装／更新成功数；跳过不抵消其他失败。Homebrew 合法别名按实际元数据规范化并去重；同一 npm 包的冲突版本输入拒绝准备。npm 自身在同环境批次中最后执行，预览与结果保持相同顺序。uninstall 只接受单个目标，已开始的任务不提供手动停止。
- 不做事务承诺或自动回滚。成功、失败、内部取消和无法确认的项目分别呈现。
- 退出保护覆盖仍在运行的任务；任务所有者结束、超时或 App 生命周期回收时，通过既有进程组生命周期终止对应子进程。

### 7.3 环境安装

- Command Line Tools：只调用 `xcode-select --install` 请求 Apple 文档定义的系统安装对话框。Cellar 不下载、不打包、不模拟 CLT 安装器，也不代替系统处理许可或安装。
- Homebrew：只接受 Homebrew 官方仓库 latest stable Release 中适用于当前平台的精确 `Homebrew.pkg`，并要求同一官方 Release 提供该资产的有效 SHA-256。Cellar 必须依次验证官方来源、SHA-256 完整匹配、package signature 和 Gatekeeper assessment；任一验证缺失、无效、不匹配或失败时都不得打开安装包，而是显示具体原因和 Homebrew 官方网站链接。
- 通过全部验证后，Cellar 只把 package 交给 macOS 系统 Installer 打开。Cellar 不保证 Installer 将显示哪一种提示；后续可能出现的权限说明、许可、认证和安装均由系统界面处理。Cellar 不重写 Homebrew 安装逻辑、不运行网络脚本、不收集管理员密码；安装引导不提供自己的 `sudo` 或 Privileged Helper。
- 已有但损坏或来源不明的 Homebrew 不被覆盖、删除或“自动修复”；界面说明检测结果并引导用户采用 Homebrew 官方恢复方式。
- nvm：1.0 提供状态、官方安装指引和已有 nvm 环境管理；不在 App 内执行远端安装脚本。

release metadata、下载、SHA-256、package signature、Gatekeeper assessment 和打开 Installer 必须是可替换边界，以便自动测试覆盖每一种 fail-closed 结果，只使用本地 fixture，绝不打开真实 Installer。

### 7.4 明确禁止

Cellar 1.0 不会：

- 执行 Homebrew cleanup、自动删除孤儿依赖、清空全局 Homebrew 缓存，或删除确认计划以外的 Cask 残留；
- 把整个 Homebrew 进程提权、内置常驻特权服务、收集或保存密码，或绕过 macOS 授权及隐私保护；
- 修改 `.zprofile` 正文、运行 `chsh`、删除 Oh My Zsh 或接受任意 Git URL/任意 Shell 命令；
- 驱动 Homebrew 或 Zsh 的交互菜单；
- 管理 npm 项目依赖，或把不同 Node 环境的全局包合并；
- 在未确认的 provider/type 之间混合批量命令；
- 后台驻留、退出后继续任务、收集遥测或使用 Cellar 账户服务。

### 7.5 Cask 关联数据清理

- 增强卸载的应用身份和关联路径绑定本机安装记录，不以最新版目录规则替代已安装版本的删除依据；正常退出等待与进度回调结束后、Homebrew 写操作前再次复验安装状态、记录和应用文件身份，记录不完整时保留关联数据。
- 完成时只复查本次确认的路径，以最终观察覆盖此前进度：重新出现的路径显示保留，并可在访达定位；授权中断后已确认不存在且 Homebrew 安装状态已确认移除的路径仍显示已移除，仅未解决路径保留失败原因。内部取消须立即停止后续删除，仍保留此前已确认的安装移除事实并完成有界只读复查。安装状态未知或路径无法复查时显示未验证，不显示移除成功。
- 完成后的保留原因分别提示：普通未移除项可在访达手动处理；共享或归属不明项须先确认影响；卸载前因应用运行而失败时可退出后重新分析；Homebrew 已确认移除软件包、仅关联路径保留时，提示退出关联进程、检查授权或核实归属后通过访达处理，不再要求用户从已消失的软件卡片重新卸载。不得将主动保护的数据统一提示为应删除的残留。清理阶段的应用重新运行、授权未完成、权限不足和状态变化必须在原弹窗对应路径显示原因与恢复建议，不退化为统一手动删除提示。
- 普通权限与管理员权限的清理期间均监测目标重新运行，并在逐文件删除边界停止后续清理、保留部分完成结果。任何受保护子路径都必须阻止祖先整体删除；大小写或 Unicode 别名、扫描中断不能绕过保护。
- 范围只覆盖选定的 Homebrew Cask，不把非 Homebrew 软件纳入管理；Formula、npm 与 Node 原有操作语义保持不变。
- 确认清单区分 Homebrew 负责的应用本体、可移除的目标关联路径和必须保留的共享或不明归属路径。设置与应用数据的永久删除须在确认中明确说明，不承诺可撤销或完全无残留。
- 本机 App 信息、同系列或同 Bundle ID 的其他副本、读取不完整的安装信息和共享 App Group 均参与保护判断。同一物理应用位置的系统路径别名不视为另一个副本，正常退出也须识别该别名；真实的其他副本继续保护。本地挂载卷仅在核对挂载身份后，按有界应用发现范围检查顶层应用与 Applications；不因存在挂载就直接保护全部关联数据，也不宣称已扫描磁盘任意位置。非本地卷、无法完整检查或身份变化仍按未知处理。用户文稿目录、整级厂商目录与未确认路径不能因为名称相似被删除。
- 下载缓存只处理 Homebrew 明确返回的目标 Cask 下载及其关联入口；仅凭名称命中的旧缓存、同名包或其他项目共享的下载保留，不扩大到 Homebrew 全局元数据、缓存、日志或其他依赖。
- 确认后、Homebrew 写操作前复验目标状态和清单，请求精确匹配的运行应用正常退出，并有界等待其实际结束；拒绝、超时或身份不一致时不强杀、不继续。删除每个路径前再复验身份及运行状态；状态变化时拒绝旧计划。Homebrew 卸载返回成功且安装状态复查确认目标不再安装后，才允许额外清理。Homebrew 卸载失败或状态未知时不补删文件。
- 额外清理遇到权限不足时，可请求 macOS 系统管理员授权，只重试允许范围内、身份仍匹配的路径。Cellar 不读取或保存密码，不把整条 brew 命令提权，也不绕过完全磁盘访问权限等系统保护。授权等待或清理期间目标应用重新启动时，撤销清理授权并停止后续删除。取消授权或删除失败时保留已完成事实、剩余路径及逐项原因。授权执行须绑定当前运行 App 的固定代码身份；待执行代码被替换、签名无效或无法验证时拒绝执行。
- Homebrew 卸载钩子本身需要 sudo 的情况尚不能转换为此授权流程；增强卸载禁止 Homebrew 自行 sudo，并按真实结果显示失败或部分完成。不能把残留清理授权表述为支持所有需要管理员权限的 Cask 卸载。

## 8. 文件、网络与隐私

Cellar 没有账户、遥测或自有服务端。网络请求只服务于用户可见的版本、目录、软件图标、包管理、插件或更新任务。除 CaskFlow 图标经 `cdn.jsdelivr.net` 获取外，使用官方服务或用户明确配置的 Tap/Registry/GitHub 地址。图标请求会向第三方 CDN 暴露所请求的 Cask token 和通常的网络连接信息；不发送本机路径、Node 环境或软件操作记录。图标缓存位于 `~/Library/Caches/com.dylanwang.Cellar/CatalogIcons/`，内存上限 8 MiB、磁盘上限 64 MiB，成功缓存 7 天，失败在当前会话内缓存 5 分钟。软件 Logo 商标权益归各自权利人，保留 CaskFlow 来源及 MIT 许可说明。

Manager 只读资源从 App Bundle 安装到：

```text
~/Library/Application Support/Cellar/Managers/<version>/
```

App Bundle Resources 不写入运行数据。文件日志位于 `~/Library/Logs/Cellar/`，适用 §4.6 的去敏、保存期限与容量限制；原始命令和 stdout/stderr 不进入日志。旧 `~/Library/Application Support/Cellar/Activity/activity.json` 不再读取、写入、迁移或自动删除。

Homebrew 和 npm 查询也可能访问网络并写入各自 cache。拒绝网络或单一来源失败时，本地已知状态尽量继续展示。任何真实安装、更新、卸载或配置操作只在用户动作和上述确认边界内发生。

## 9. 性能与可靠性

- 启动先读取本地状态；线上版本检查不阻塞首屏。
- 相互独立的只读 IO 使用有界并发；不使用轮询循环、高频动画或投机 cache。
- 进程使用绝对 executable、参数数组、受控 environment、明确工作目录/stdin/stdout/stderr、deadline、输出上限、取消和进程组回收；禁止 `bash -c`。
- 读取、线上版本、搜索和单项 mutation 的失败分开建模；一个错误不清空无关成功数据。
- View 不直接运行命令；Models 不执行 IO；自动测试不接触用户真实环境。

## 10. 发布范围与非目标

1.0 支持 macOS 26.0 及以上、仅 Apple Silicon `arm64`，使用 Swift 6、SwiftUI、Foundation 和必要的 AppKit/Sparkle。不支持 Intel、Universal Binary、Rosetta、macOS 15、App Sandbox 或 Mac App Store。

1.0 不保证自定义 `NVM_DIR`、asdf、fnm、Volta、远程主机、团队同步、后台自动更新包、自动修复开发环境或任意 CLI 执行。新的删除、提权、持久化或外部协议能力必须先更新本文的产品与安全契约。

## 11. 验收边界

自动测试和无签名构建验证类型、状态、解码、进程、取消、持久化、测试隔离、localization coverage、最低系统和 arm64 产物。所有外部写操作使用 fake executable、fixture 和临时目录。

真实 Finder 启动、系统授权、官方 Installer、真实 Homebrew/npm/nvm、网络、窗口、键盘、VoiceOver 和视觉质量按[人工验收清单](../manual-smoke-checklist.md)验证。未执行的项目不得描述为已验证或已发布。
