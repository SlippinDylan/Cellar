## 1. 内置批量安装清单放哪些 global package

历史问题：

- 第一版的 `INSTALLABLE_GLOBAL_PACKAGES` 到底包含哪些包
- 是否按类别分组

当前结论：

- 默认清单保持为空，保留用户配置结构，不内置任何真实包
- 等你后续给出个人常用清单后再补

历史考虑：

- 结构先落地更重要
- 避免实现 agent 替你猜测个人工具偏好

## 2. 保护包列表是否只包含 `npm` 和 `corepack`

历史问题：

- 是否还要保护 `npx`
- 是否还要保护其他你常用的基础 CLI

当前结论：

- 保护 `npm` 和 `corepack`

历史考虑：

- 这是最低安全基线
- 其余工具是否应保护具有明显个人偏好色彩

## 3. 第一版源管理是否开放全部写操作

历史问题：

- 第一版是否允许完整执行：
  - `npm config set registry`
  - `npm config set @scope:registry`
  - `npm config delete @scope:registry`

当前结论：

- 允许这些写操作
- 但必须逐步确认，并在写入后验证读取结果

历史考虑：

- 这是“源管理”存在的核心价值
- 只读模式对第一版来说过于保守

## 4. 清理 cache 时是否允许直接删除 cache 目录

历史问题：

- 除了 `npm cache clean --force`，是否允许脚本直接删除 cache 路径

当前结论：

- 优先执行 `npm cache verify` 和 `npm cache clean --force`
- 直接删除目录仅作为候选动作，不作为默认动作

历史考虑：

- 更接近 npm 自身的支持路径
- 误删风险更低

## 5. `指定项目 Node 版本` 是否进入第一版

当前结论：

- 已纳入终版，并通过交互路径确认与 JSON/App 外部写入门禁保护

历史考虑：

- 第一版重点应放在全局环境管理
- 这个功能涉及项目路径输入、`.nvmrc` 写入、`engines.node` 读取，复杂度偏高

## 6. 第一版是否实现并行安装

当前结论：

- 不实现并行安装；这是长期安全权衡，不是终版缺口

历史考虑：

- npm 全局安装并行收益有限
- 失败排查和环境竞争问题更复杂

## 7. Node 版本卸载是否纳入第一版

当前结论：

- 已纳入终版，当前版本、默认版本和仍有用户全局包的版本受保护

历史考虑：

- 这属于高风险破坏性动作
- 先把安装、切换、扫描和提示做稳更合理

## 8. Shell 兼容范围是否只做 zsh

当前结论：

- 产品环境仍是 macOS 终端；实现与测试脚本兼容系统 Bash 3.2，交互入口可从 zsh 启动

历史考虑：

- 你的主要使用场景已经明确是 macOS 默认 shell
